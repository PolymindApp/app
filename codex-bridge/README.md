# Polymind Codex bridge

This separately hosted service keeps ChatGPT authentication out of the PHP web host. It starts one isolated Codex App Server session per Polymind account and uses the stable stdio JSON-RPC transport internally.

## Run locally

Install Codex CLI 0.147.0 or newer so App Server includes the device-code flow, then set a bridge token shared only with the PHP API:

```bash
export MOM_CODEX_BRIDGE_TOKEN="replace-with-at-least-32-random-characters"
pnpm codex-bridge
```

The defaults listen on `127.0.0.1:8091`, invoke `codex` from `PATH`, and persist per-account Codex homes under `private/codex-bridge`.

| Variable | Purpose | Default |
| --- | --- | --- |
| `MOM_CODEX_BRIDGE_TOKEN` | Bearer token required on every account route | Required |
| `MOM_CODEX_EXECUTABLE` | Codex CLI executable | `codex` |
| `MOM_CODEX_BRIDGE_DATA` | Persistent root for isolated account credentials | `private/codex-bridge` |
| `MOM_CODEX_SESSION_IDLE_MS` | Idle process shutdown delay | `300000` |
| `HOST` | HTTP listen address | `127.0.0.1` |
| `PORT` | HTTP listen port | `8091` |

## Container deployment

Build from the repository root:

```bash
docker build -f codex-bridge/Dockerfile -t polymind-codex-bridge .
docker run --rm \
  -p 127.0.0.1:8091:8091 \
  -e MOM_CODEX_BRIDGE_TOKEN="replace-with-at-least-32-random-characters" \
  -v polymind-codex-data:/var/lib/polymind-codex \
  polymind-codex-bridge
```

Keep the bridge on a private network when possible. If the PHP host reaches it over the public internet, terminate TLS in front of it and restrict inbound traffic to the PHP host. Never expose the bridge token to the browser.

The data volume contains refreshable ChatGPT credentials. Back it up and protect it like a secrets store. Each account directory is keyed by a one-way subject generated by the PHP API rather than a Polymind user ID.
